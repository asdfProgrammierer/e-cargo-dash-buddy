# Project rules

- Driver schedule date expansion and planned-time validation live in `src/lib/driverScheduleDates.ts`; planned start times are per-day local clock values restricted to the 15-minute rhythm (00, 15, 30, 45) via `QuarterTimeSelect`, separate from actual work sessions, so scheduling cannot change payroll statistics.

- All order geocoding goes through the `geocode-address` edge function (client: `src/lib/geocodeOrder.ts`, server batch: `regeocode-pickup-orders`), which stores `geocode_quality`/`geocode_note` on orders — so imprecise positions (wrong/missing house number, other postcode) are flagged consistently everywhere.
- A DB trigger clears coordinates and geocode quality when an order's recipient address changes — so a stale pin is never kept for a new address.
- Shopify webhook settings use the admin-guarded `shopify-webhook-setup` save/status actions; return only secret-presence flags, preserve empty secret inputs and existing activation cutoffs, so edits remain durable without exposing credentials or skipping pending orders.
- Driver PINs are stored in Auth as PIN plus a username-bound suffix (`driverAuthPassword`, mirrored in `src/lib/driverPin.ts` and `supabase/functions/_shared/driver-pin.ts`) — the leaked-password check rejects plain short numeric PINs; login falls back to the raw PIN for legacy accounts.
- Shopify delivery-status sync runs inside the `shopify-push-fulfillments` cron (per-connection `sync_delivery_status` flag, last sent event in `orders.shopify_event_status`) — one job owns all Shopify write-backs, and events are only re-sent when the mapped status changes.
- Driver schedule statuses are admin-editable rows (driver_schedule_statuses, FK from driver_schedules.status); availability logic uses the is_duty flag, never hardcoded keys, and statuses still in use are deactivated instead of deleted.
- Driver schedule range/recurrence saves share a `series_id`; single-day same-status edits preserve it, new assignments replace it, and deletion is scoped to the driver and original series so unrelated absences remain untouched. Legacy groups use original creation timestamp and status, never status alone.
- Revenue/cost analysis math lives in pure `src/lib/profitability.ts` (tested); the Statistik tab only loads data — so billing rules stay testable and consistent between driver and merchant views.
- Merchant cost shares on shared tours are split by each stop's marginal detour (`route_stops.detour_duration_s`, computed in `optimize-route` from in/out legs minus estimated direct link) plus stop time, falling back to stop count when any stop lacks it — so remote customers carry their own way in and out.
